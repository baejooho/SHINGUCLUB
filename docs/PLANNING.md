# SHINGUCLUB — 기획서 및 요구사항 정의서

## 1. 프로젝트 비전

신구대학교 학생들이 동아리 정보를 한곳에서 찾고, 가입을 신청하며,
가입 이후에는 공지·일정·회원 정보를 확인할 수 있는
동아리 관리 웹 서비스를 만든다.

기존에 분산되어 있던 동아리 홍보·가입·일정 안내를
웹 기반으로 통합하는 것이 목표이다.

## 2. 문제 정의

- 동아리 정보가 SNS·포스터·지인 소개에 흩어져 있어 찾기 어렵다.
- 가입 신청과 승인 절차가 카톡·대면 중심으로 비효율적이다.
- 회장이 회원·공지·일정을 한곳에서 관리하기 어렵다.
- 학생 입장에서 “내가 어느 동아리에 신청/소속인지” 상태가 불명확하다.

## 3. 핵심 요구사항 (기능 요구사항)

| ID | 요구사항 | 설명 |
|----|----------|------|
| FR-1 | 동아리 목록 | Firestore `clubs` 컬렉션에서 동아리 목록 조회, 페이지네이션 |
| FR-2 | 동아리 상세 | 동아리 소개, 가입 상태(none/pending/approved) 표시 |
| FR-3 | 가입 신청 | 로그인 사용자가 동아리 가입 신청 (`clubApplications`) |
| FR-4 | 가입 승인 | 회장이 신청을 승인/거절, 승인 시 `members`에 등록 |
| FR-5 | 회원가입/로그인 | Firebase Auth 이메일·비밀번호 인증 |
| FR-6 | 이메일 인증 보조 | EmailJS 등을 활용한 가입 보조 플로우 |
| FR-7 | 프로필 | 프로필 조회 및 수정 |
| FR-8 | 공지 | 동아리별 공지 목록/상세 |
| FR-9 | 일정 | 캘린더 기반 일정 조회(날짜별) |
| FR-10 | 회원 목록 | 동아리 소속 회원 목록 확인 |
| FR-11 | 회장 권한 | `role === president`인 사용자만 admin 화면 접근 |

## 4. 비기능 요구사항

- 반응형 UI: 모바일·데스크톱에서 동아리 목록/상세 이용 가능
- 실시간성: Firestore 기반 데이터 조회 (필요 시 확장으로 스냅샷 구독)
- 권한 분리: 일반 회원과 회장 기능 분리
- 학습용 범위: 학교 동아리 규모에 맞는 CRUD 중심 구현

## 5. 향후 확장 계획 (Future Work)

- 알림(가입 승인, 공지 등록) 기능
- Vercel 배포 및 운영 모니터링
